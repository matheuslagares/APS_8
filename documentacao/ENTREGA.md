# Checklist de preparação e entrega

O fluxo móvel definido usa **Expo Go**. Este checklist organiza o trabalho final do grupo e não declara atendimento automático à rubrica da instituição.

## Confirmar as exigências recebidas

- [ ] Registrar data, horário e canal de entrega: ____________________.
- [ ] Conferir modelo do relatório, limite de páginas e padrão de referências.
- [ ] Confirmar quais quatro diagramas e qual notação o professor exige.
- [ ] Conferir fichas individuais, identificação dos integrantes e demais anexos exigidos.
- [ ] Confirmar tempo disponível e recursos de rede/projeção para a apresentação.

## Conferir a versão do projeto

- [ ] Registrar o commit apresentado: ____________________.
- [ ] Seguir o [README](../README.md) em um computador de demonstração e conferir `/saude`.
- [ ] Verificar o Expo SDK 57 com a versão do Expo Go instalada em cada celular.
- [ ] Executar os testes da versão de entrega e guardar as saídas; usar [TESTES.md](TESTES.md).
- [ ] Fazer os testes físicos pendentes: cadastrar no A, consultar no B, resolver no B, atualizar no A e reiniciar a API preservando o dado.
- [ ] Registrar aparelhos, versões, data, responsáveis e evidências sem substituir o ensaio físico por navegadores.

## Preparar os materiais

- [ ] Revisar e completar [RELATORIO_BASE.md](RELATORIO_BASE.md) com informações reais.
- [ ] Revisar os diagramas de [ARQUITETURA.md](ARQUITETURA.md) conforme as exigências confirmadas.
- [ ] Completar o [diário](DIARIO.md) e as fichas com autoria e horas efetivamente realizadas.
- [ ] Separar somente evidências correspondentes à execução relatada e identificar testes não executados.
- [ ] Identificar gravações web como clientes de navegador; confirmar sua aceitação como apoio com o professor.
- [ ] Conferir se todos os arquivos citados no relatório estão presentes no material entregue.

## Ensaiar e preservar

- [ ] Ensaiar o roteiro de [APRESENTACAO.md](APRESENTACAO.md) e medir o tempo.
- [ ] Verificar se todos os integrantes explicam o caminho aplicativo → HTTP/JSON → API → SQLite.
- [ ] Usar dados fictícios e informar que os relatos não são verificados nem alertas oficiais.
- [ ] Explicar acesso sem login, atualização manual, servidor único e ausência de tolerância a falhas.
- [ ] Parar a API e copiar `backend/alagamentos.db` para um backup separado do Git.
- [ ] Guardar uma cópia do código e das evidências fora da máquina de demonstração.
- [ ] No dia, conferir Wi-Fi, IPv4, `.env`, API, Expo e `/saude` nos celulares antes da apresentação.
